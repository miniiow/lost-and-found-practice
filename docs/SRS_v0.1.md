# 소프트웨어 요구사항 명세서 v0.1 — 교내 분실물 서비스

## 확정 사항

액터(시스템과 직접 상호작용하는 역할)는 **분실 학생, 습득 학생, 행정 담당자**의 3명이다. 유스케이스(사용자가 하나의 목표를 달성하는 서비스)는 화면·버튼·DB 저장 단계로 나누지 않는다.

| 구분 | 확정 내용 | 출처와 적용 |
| --- | --- | --- |
| 액터 | 분실 학생 / 습득 학생 / 행정 담당자 | 고객 검토 완료 지시; 원문 §2, S1·S2·S3 |
| 학생 등록 | 습득 학생이 주운 물품을 앱으로 바로 등록한다. | 고객 검토 완료 지시; FR_04, UC_03. 원문 S3만으로 등록 기능을 도출한 것은 아니다. |
| 센터 등록 | 행정 담당자가 분실물 센터에 접수된 습득 물품을 관리하려고 등록한다. | 고객 검토 완료 지시; NEEDS_2·SC2·S2; FR_07, UC_05 |
| 모델링 판단 | 학생 앱 등록과 센터 접수 등록을 별도 UC로 모델링한다(분석 결정; 고객 검토 완료 사항과 구분). | 주체·시작 상황·목표가 다름. 화면이나 저장 기능의 차이 때문이 아니다. [논의] Q_05: 입력·처리 차이가 없다면 하나의 UC에 두 액터를 연결하는 안을 재검토한다. |

## 작성 기준과 근거 읽는 법

업무 요구의 유일한 원문은 [고객 요구사항 원문](./고객%20요구사항.md)이다. S1~S5는 §3 인터뷰, SC1~SC8과 C_1은 §4 범위·제약, NEEDS_1~NEEDS_7은 §5 요약의 위치를 가리킨다. 고객 검토 완료 지시는 이번 작업의 명시적 확정 사항으로 별도 표시한다. 기존 SRS·UC·RTM은 원문 근거가 아니다.

추적성(결과 항목의 출처와 후속 모델을 따라가는 성질)은 원문 위치 → FR/NFR/Pol → UC로 유지한다. **[가정]**은 검토용 제안이며 승인된 요구가 아니다. **[논의]**는 확인이 필요한 결정이다. 우선순위 ‘높음’은 포함 범위에 대한 분석자 제안이며 구현 순서 합의는 Q_15에서 확인한다.

## 비기능 요구사항

품질 분류는 과제에 제시된 ‘사용성’ 용어에 맞춰 [ISO/IEC 25010:2011 품질 모델](https://www.iso.org/obp/ui/?_escaped_fragment_=iso%3Astd%3Aiso-iec%3A25010%3Aed-1%3Av1%3Aen)을 사용한다. 개정판인 [ISO/IEC 25010:2023](https://www.iso.org/cms/%20render/live/en/sites/isoorg/contents/data/standard/07/81/78176.html)의 용어 전체를 혼용하지 않는다. 표준은 분류 참고이며 업무 요구의 추가 근거가 아니다. 원문에 없는 유지보수성·호환성 목표는 임의로 추가하지 않았다.
